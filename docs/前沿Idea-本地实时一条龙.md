# PianoFlow 前沿 Idea：本地实时一条龙

> **本文锁定「前沿」主张与证明优先级。** 与 [产品定位-一条龙体系.md](./产品定位-一条龙体系.md) 配套：总纲管身份，本文管**技术 idea**。  
> 对应原则「前沿」：低延迟音频、流畅画面、清晰判定；**本地轻量分析**；不做云端大模型教琴。  
> 锁定：2026-08-12

---

## 1. 主张（一句话）

**整条龙在本地跑通，并且每一环都要又快又稳：**  
听歌成谱要快、跟弹判定要快、下落 / 琴键 / 五线谱要对齐——**不靠云、不靠大模型聊天装老师**。

不是三个互不相干的功能，而是同一条**本地实时练琴流水线**上的三块硬指标，互相卡着还要一起好。

---

## 2. 三块「更加好」（相对「能用」）

### 2.1 跟弹体感（最高优先）

- **要什么**：按下键后，很快知道对不对、该不该往下推；多音尽量稳；开着示范音也不乱判。  
- **不是什么**：只是「接上了麦克风模型」。  
- **更好**：体感接近实时，明显慢半拍就不算达标。  
- **技术方案整理**：见 [音高识别-最优技术方案.md](./音高识别-最优技术方案.md)。

### 2.2 本地成谱（次优先，秒级）

- **要什么**：音频（可含分离）→ 练习用谱，在**本机**完成；出完能直接进跟弹。  
- **不是什么**：上传云端等很久；也不要求出版级音高正确率（见总纲：成谱 = 练习用谱）。  
- **更好**：**控制在秒级**（体感 / 演示：数秒量级出可练结果，而不是分钟级干等）。具体秒数可随模型与曲长再标定，但叙事与验收以「秒级」为约束，不做「慢慢批处理」。

### 2.3 三路不明显漂（第三优先）

- **要什么**：下落、琴键高亮、五线谱游标（及示范音）像同一个节拍在走。  
- **不是什么**：三个区域各自在动就算完事。  
- **更好**：正常播放时肉眼不明显漂；暂停 / 拖进度 / 变速后仍能重新对齐。

---

## 3. 证明优先级（已拍板）

排期与验收时按此序，**不要颠倒**：

1. **跟弹体感** >  
2. **成谱（秒级）** >  
3. **三路不明显漂**

含义：

- 先把「听你弹 → 判定 → 推进」做得快而稳；  
- 再把「材料 → 可练谱」压到秒级本地链路；  
- 同步问题持续修，但不以牺牲跟弹体感为代价去堆同步花样。

冲突时：跟弹体感优先；成谱为赶秒级不得毁掉跟弹主链路；三路同步服从前两者的时钟与性能预算。

---

## 4. 和「基础功能」的差别（防写成功能清单）

| 普通说法 | 本文 idea |
|----------|-----------|
| 能跟弹 | 跟弹要**快、稳、可测** |
| 能出谱 | 本机出谱且**秒级**，出完就能练 |
| 有三个画面 | 三路**不明显漂**，共一时钟 |
| 用了 AI | **本地轻量**，为练琴实时链路服务，不是云端私教 |

答辩 / 对外可用句：

> 我们不做云端 AI 老师，把前沿做在**本地实时练琴流水线**上：跟弹体感第一，成谱秒级第二，三路对齐第三。

## 5. 粗验收（可后补精确数字）

| 项 | 合格方向（已定） | 待标定 |
|----|------------------|--------|
| 跟弹体感 | 体感不慢半拍；有/无示范音都少乱推 | 可补：端到端延迟 ms、误推进率 |
| 成谱 | **秒级**出可练谱并进入练习 | 可补：按曲长的秒数上限、机型 |
| 三路同步 | 正常播放肉眼不明显漂 | 可补：漂移上限（拍 / ms） |
