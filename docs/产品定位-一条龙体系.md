# PianoFlow 产品定位：一条龙练琴体系

> **本文是产品「不忘本」总纲。** 改需求、排期、加功能前先读本节。  
> 现行界面与实现细节仍以 [需求汇总.md](./需求汇总.md) 为准；本文管的是**身份与总图**，不是某一屏的控件清单。  
> 锁定：2026-08-11

---

## 1. 一句话身份

**PianoFlow = 多源进料 → 自动成谱 → 跟弹练习 → 反馈再练 的一条龙练琴体系。**

- 不是「仿 Flowkey 的练习页 App」  
- 不是「单独的分轨 / 识谱 / 跟弹工具拼盘」  
- 而是：**同一套闭环里，允许歌曲音频、库内曲、曲谱 PDF 等多种材料进来，变成可练对象，练完给出反馈并驱动下一步**

对外可说：

> 听到一首歌、或打开库里的曲子、或拿一份谱的 PDF——进得来、成得了谱、练得上、知道下一步练什么。

---

## 2. 体系总图（完整，不砍入口）

进料层**并列**，都是正统入口；练习与反馈是**唯一中轴**。

```text
进料层（并列）
  · 音频（流行歌 / 录音等；可含音源分离）
  · 系统曲库已有曲子
  · 曲谱 PDF / 图片
  · 已有数字谱（MusicXML 等，若有）
        ↓
成谱层
  · 统一产出「练习用谱」+ 跟弹时间轴事件
  · 允许草稿 / 自动稿；不把自动成谱承诺为教材级真理
        ↓
练习层（中轴）
  · 下落 + 88 键高亮 + 五线谱同一拍
  · 跟弹 / 自动播放 / 慢速 / 单手 / 循环 …
  · 真琴：麦克风识音驱动跟弹（不以 MIDI 设备为主路径）
        ↓
反馈层
  · 对错、命中、难点小节等可感知结果
        ↓
再练层（闭环）
  · 弱项任务（慢速 / 单手 / 循环片段）
  · 可选：降难一档再练、同技巧下一首、再录对比等
  · 目标：练完不是「看完分数就走」，而是回到可执行的下一步
```

**完整体系 = 多入口 + 单中轴。**  
某一入口成熟度暂时落后，**不等于否定总图**；排期可以有先后，身份不能改回「只有练习页」。

---

## 3. 成谱在体系里的诚实角色

本体系的卖点是 **通路与闭环**，不是「自动生成 = 原作 100% 一致」。

| 说法 | 是否采用 |
|------|----------|
| 自动稿 / OMR 稿 / 音频转录稿 → **练习用谱**，能练、能跟弹 | ✅ |
| 把未校对自动稿标成「正式教材谱」骗人 | ❌ |
| 体系成功 = 进料→成谱→练习→反馈→再练不断链 | ✅ |
| 体系成功 = 自动谱达到出版级音高正确率 | ❌（不作第一成功标准） |

工程上仍可保留 `formal` / `omrDraft` 等质量标注与护栏（见曲谱 SOP），那是**诚实标注**，服务本条，而不是把产品重新定位成「校对工厂」。

---

## 4. 约束与边界（防跑偏）

写进总纲，避免改着改着变回别的产品：

1. **一条龙是本，练习页是中轴零件**  
   优化跟弹手感、可视化、性能，都应服务「材料进得来 → 练得上 → 有下一步」，不能把项目叙事缩回「只做 Flowkey 克隆」。

2. **不做课平台 / 会员墙 / 社交 / 重后端**（与需求汇总一致）  
   「再练」是个人闭环里的任务与反馈，不是运营课表中台。

3. **MIDI 设备不是主路径**  
   硬件演示与测试条件不足；主路径保持麦克风 + 真琴（或系统示范）。不把「接 MIDI 键盘」写成体系前提。

4. **本地优先**  
   分轨 / 转录 / OMR 可以分步接入，优先可本地或可离线演示的链路；不为「云端 AI 老师聊天」改身份。

5. **不杂烩**  
   进料可以多，**练习主布局与主循环仍只保留一种**；新能力挂在龙的某一环上，不另开互抢注意力的第二产品。

6. **成熟度可以不齐，总图不能拆**  
   演示或迭代允许「先打通曲库→练习→反馈，再补音频分离→转录」等，但文档与排期须标明缺的是哪一环，而不是默默删掉该环。

## 5. 每一环的「最小合格」（不忘本检查单）

改功能前问：这一环有没有变弱或被删？

| 环 | 怎样算「通了」（最小） | 落地备忘 |
|----|------------------------|----------|
| 进料·音频 | 能提交一首音频并进入后续成谱流程（分离可为可选增强） | 工坊「导入音频」+ `audio_to_practice_draft.py`（hop0.4 / 最长45s预览→userImport→自动进练） |
| 进料·曲库 | 库内曲一键进入练习中轴 | 已有 |
| 进料·PDF | 能提交 PDF/图并进入成谱（OMR 或等价） | 工坊 PDF **一键流水线**（暂存→启动 OMR→轮询扫描→导入→进练，草稿）；图入口未接 |
| 成谱 | 产出可被练习引擎加载的练习用谱 + 时间轴；质量档诚实 | 音频/MIDI→草稿已通；导入成功自动进练习；正式校对另线 |
| 练习 | 跟弹主循环可用（可视化 + 识音或示范推进） | 已有；命中闪字 + `hit-latency` 日志可观测 |
| 反馈 | 练完有可理解的结果（至少命中/对错类） | 结算 + 实时 perfect/good 闪字 |
| 再练 | 至少一种「根据结果生成的下一步动作」（如弱项循环） | **结算页「练薄弱段」**：按 miss 拍聚类开循环再练 |

### 体系成熟度（诚实，2026-08-13 · 体系通关已冻结）

| 环 | 状态 | 一句话 |
|----|------|--------|
| 曲库→练习→反馈→弱项再练 | **通** | 最小中轴已闭环 |
| 音频→草稿→自动进练 | **通** | 可选 Demucs；无则跳过并诚实标未分轨 |
| PDF→成谱 | **通** | 工坊一键 OMR→导入→进练（草稿） |
| 跟弹体感 / 三路 | **通** | 判定/闪字/可观测；单时钟+冻结停 metro |
| formal 校对生产线 / 跨平台 Verovio | **战役外** | 护栏/平台，非通关前置 |

曲库 + 练习已强；**体系通关 = 三入口都通 + 前沿可用**（已冻结），见 §5.1。
