## 0. 硬约束：实时 × 准确 × 抗干扰（三者同时达标）

练习跟弹听音 **必须** 高实时 + 高准确 + **强抗干扰**。  
慢而准、快而飘、安静室准一开示范就误推——都算不合格。  
不以 MAESTRO 离线 note-F1 为验收；以「按下 → 判定」手感 + 错漏多/误推进 + **干扰条件下不崩**为准。

### 0.1 实时 SLO（真机 `PracticeHitLatency`，capture→判定）

| 指标 | 目标 | 说明 |
|------|------|------|
| hop | ≤ 30ms | 与现网 `PitchService` hop≈30ms 对齐 |
| 模型前瞻 / look-ahead | **0ms（严格因果）** | 禁止秒级右上下文；BP 全窗 ~2s 只作特征教师，上线推理须流式 |
| 单次推理 | p95 ≤ 20ms（中端 Android / Win CPU） | 超预算则降特征维 / 减头，不堆大模型 |
| 端到端 capture→hit | **p50 ≤ 80ms，p95 ≤ 150ms** | guide 开/关分列；超标不上主路径 |
| 忙时策略 | 只留最新 hop，丢弃过期窗 | 已有：infer busy 时不背压排队 |

### 0.2 准确 SLO（同一评测表，相对 `basic_pitch_latch`）

| 指标 | 目标 |
|------|------|
| onset F1 @±50ms | ≥ latch，且慢练干净段接近饱和 |
| 错漏多 macro-F1 | **明显高于** 纯 BP / latch 规则映射 |
| 误推进（false-advance） | **低于** latch；开 `guide_audio` 时尤严 |
| 卡死（stuck） | 慢练 `hit` 接近 0；不得靠「抬高阈值拖死」换低误推 |
| 有/无示范音 | 两条件都要达标，禁止只报 guide-off |

### 0.3 抗干扰 SLO（练习场景主战场）

干扰按优先级验收；**开示范音** 是第一干扰源，不是边角。

| 干扰类型 | 现象 | 目标 | 现网锚点 / 评测 |
|----------|------|------|-----------------|
| **扬声器示范 bleed** | guide 音进麦 → 误推进 | guide-on 误推进 **≤** guide-off×1.5，且 **低于** latch；用户未弹不得推进 | `guide_audio=true` 子集；`CueBleedGuard` / `GuideRetriggerGate` |
| **延音 / 同音再击** | sustain 当新 onset；连击被吞 | 同音再击可推进；纯延音不误推 | `AttackLatch` + onset flux；评测 `extra`/`hit` |
| **邻音串音 (±1)** | bleed/估点落邻键 | waiting 条件头不把 ±1 当 hit；wrong 可报 | 金标 `wrong`；chord 条件 |
| **环境底噪 / 风扇 / 人声** | 假 onset、锁死抖动 | 干净慢练 stuck≈0；底噪段 false-advance 不劣于 latch | 采集矩阵加「有底噪」行（真数） |
| **踏板 / 共鸣 / 房间混响** | 尾音拖长误判 | 不靠无限抬阈值；onset 边沿 + quiet gap | 真机抽测；与 latch quiet 对齐 |
| **多键和弦** | 只听到部分音 | 按 waiting_chord 集合判定；部分命中策略与引擎一致 | `waiting_chords` / `chord` 字段 |

**禁止的「伪抗干扰」：** 全面抬阈值、加长 suppress、加 look-ahead——会牺牲实时或制造卡死，§0.1/§0.2 一并打回。

**分层：**

1. **模型内：** `guide_present`、onset 边沿、waiting 条件 → 从特征上压 bleed / 假 onset  
2. **规则门（保留）：** CueBleed / GuideRetrigger / AttackLatch —— 兜底，不替代模型学习  
3. **评测：** 主表必须 **分列 guide-on / guide-off**；抗干扰未分列 = 未验收

### 0.4 同时达标的架构（锁定）

```
短 hop 因果特征（≤30ms）
    + 冻结/蒸馏 BP 或更轻 onset 骨干（流式）
    + 条件头：waiting_chord → {hit,wrong,miss,extra}
    + onset 边沿 + guide_present 辅助（抗 bleed）
    + 现有 AttackLatch / CueBleed / GuideRetrigger（规则门，不替代模型）
```

- **准**：来自「待判和弦条件 + 练习标签」，不是更长未来窗。  
- **快**：来自因果小头 + 30ms hop + 忙时丢帧；禁止用 look-ahead 换 F1。  
- **抗干扰**：guide 条件训练 + onset/边沿头 + 规则门三联；主表分列 guide-on/off。  
- **上线门禁**：新 ONNX 必须同时打过 §0.1、§0.2、§0.3，才允许实验开关；默认仍 BP。

文献对齐（练习场景取口径，不搬模型）：交互向实时转录常以 **≈30ms** 为流畅下限、**≈10ms** 为无感目标；跟谱容忍可到数百 ms，但本产品跟弹手感按上表更严。

## 1. 数据协议（JSONL，一行一段）

Schema 见 [`testdata/practice_listen/schema.json`](../testdata/practice_listen/schema.json)。

每行字段：

| 字段 | 类型 | 含义 |
|------|------|------|
| `id` | string | 片段 id |
| `wav` | string | 相对 repo 根的 wav 路径（mono，推荐 22050 Hz） |
| `score_id` | string | 曲库 id（可空，夹具用 `synthetic`） |
| `guide_audio` | bool | 录音时是否开扬声器示范 |
| `sample_rate` | int | wav 采样率 |
| `events` | array | 金标事件 |
| `waiting_chords` | array? | 可选：时间片上的待判和弦 |

`events[]` 元素：

| 字段 | 含义 |
|------|------|
| `onset_ms` | 按下时刻（ms） |
| `midi` | 21–108 |
| `label` | `hit` \| `wrong` \| `miss` \| `extra` |
| `chord` | 可选：当时待判 MIDI 列表 |

**采集建议（真数）：** 曲库短曲 ×（正确慢练 / 故意错漏多 / 开示范音 / **有底噪或混响**）≥ 各若干段。抗干扰以 guide-on 与底噪为必采，不可只有消音室。

## 2. 指标

| 指标 | 定义 |
|------|------|
| onset F1 @±50ms / ±100ms | 预测 onset 与金标匹配（音高相同或 ±0 半音；容差取时间） |
| 错漏多 macro-F1 | 将系统输出映射到 hit/wrong/miss/extra 后分类 |
| 误推进代理 | 在不应推进窗口内产生 hit/extra 的比率 |
| 卡死代理 | 金标 hit 在容差内无对应预测的比率（≈ miss recall 反面） |
| 延迟 p50/p95 | 音频进入→事件发出；离线表为处理耗时占位，**验收以真机 PracticeHitLatency 为准**（见 §0.1） |
